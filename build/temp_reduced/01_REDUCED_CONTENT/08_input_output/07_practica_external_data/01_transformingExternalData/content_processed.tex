\subsection{Transforming External Data}

Pipeline shape: external input $\rightarrow$ Python objects $\rightarrow$ transformed objects $\rightarrow$ external output. Each stage owns one boundary crossing.

\subsubsection{Read-Transform-Write Pipelines}

Separate input and output paths; transform incrementally when possible.

\begin{verbatim}
from pathlib import Path
src, dst = Path("in.txt"), Path("out.txt")
src.write_text("homer | d'oh!\n", encoding="utf-8")
with open(src, encoding="utf-8") as fin, open(dst, "w", encoding="utf-8") as fout:
    for line in fin:
        fout.write(line.strip().upper() + "\n")
print(dst.read_text(encoding="utf-8"))
\end{verbatim}

\subsubsection{Temporary Files and Safe Output Replacement}

Write to a temporary file in the target directory, then \texttt{replace()} into the final name so consumers never observe a partial file.

\subsubsection{Separating Parsing, Processing, and Serialization Functions}

Keep \texttt{parse\_*}, \texttt{transform\_*}, and \texttt{serialize\_*} as distinct functions so failures localize and tests can target pure transformation logic.
