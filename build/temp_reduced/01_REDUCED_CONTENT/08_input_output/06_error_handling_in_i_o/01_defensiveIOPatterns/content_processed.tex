\subsection{Defensive I/O Patterns}

External state can change between inspection and use. Patterns differ in whether they probe conditions or attempt the operation directly.

\subsubsection{EAFP File Access: Trying the Operation and Handling the Exception}

``Easier to ask forgiveness than permission'': attempt \texttt{open}/read and catch \texttt{FileNotFoundError}, \texttt{PermissionError}, or broader \texttt{OSError}. The handled failure matches the attempted operation.

\begin{codebox}[]{python}{EAFP File Access: Trying the Operation and Handling the Exception}{def01}
from pathlib import Path
path = Path("maybe.txt")
try:
    text = path.read_text(encoding="utf-8")
except FileNotFoundError:
    text = ""
print(text)
\end{codebox}


\subsubsection{LBYL File Access: Checking Conditions Before Opening}

``Look before you leap'': test \texttt{exists()}/\texttt{is\_file()} first. Cheaper when failure is common and checks are cheap; vulnerable to time-of-check/time-of-use races.

\subsubsection{Atomicity Concerns: Why Existence Checks Can Become Invalid Before Use}

Another process may delete, rename, or lock a path between an LBYL check and \texttt{open()}. EAFP on the actual operation remains the robust default for correctness under concurrency.
