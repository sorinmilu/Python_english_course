\section{The I/O Boundary: From Runtime Objects to External Systems}

\subsection{Programs as Data Consumers and Data Producers}

A running program transforms data: it consumes external input, holds intermediate state as runtime objects, and may emit external output. I/O is the mechanism that makes computation externally observable and persistent.

\subsubsection{Runtime Memory vs. Persistent Storage: Why Variables Disappear but Files Remain}

A Python name binds to a heap object reachable only while the process runs. Process termination reclaims that address space. A file is an operating-system-managed persistent byte container; Python file objects are temporary handles to that external resource, not the stored bytes themselves.

\begin{verbatim}
msg = "Nobody expects the Spanish Inquisition!"
answer = 42
print(msg, answer)
print("Bindings vanish when the process exits; nothing here is persistent yet.")
\end{verbatim}

\subsubsection{Standard Streams: \texttt{stdin}, \texttt{stdout}, and \texttt{stderr} as Process-Level Communication Channels}

Every CLI process inherits three standard channels: \texttt{stdin} (input), \texttt{stdout} (ordinary output), and \texttt{stderr} (diagnostics). Python exposes them as \texttt{sys.stdin}, \texttt{sys.stdout}, and \texttt{sys.stderr}---typically \texttt{\_io.TextIOWrapper} instances with \texttt{write()}, \texttt{flush()}, \texttt{encoding}, and \texttt{isatty()}.

\begin{verbatim}
import sys

print("stdout type:", type(sys.stdout))
sys.stdout.write("Direct write without automatic newline\n")
sys.stdout.flush()
sys.stderr.write("Diagnostic on stderr\n")
user_text = input("Phrase: ")
print(type(user_text), user_text.upper())
\end{verbatim}

\texttt{input()} reads a line from \texttt{stdin} and returns a \texttt{str}; from that point the data is an ordinary runtime string.

\subsubsection{C Comparison: \texttt{printf()}, \texttt{scanf()}, File Descriptors, and Python's Higher-Level Stream Objects}

In C, \texttt{printf}/\texttt{scanf} operate on \texttt{FILE *} streams backed by small integer file descriptors (\texttt{0}, \texttt{1}, \texttt{2}). Python's stream objects sit above the same descriptor layer: they add encoding, buffering, and newline policy. \texttt{sys.stdout.fileno()} exposes the underlying descriptor when low-level access is required.

\begin{verbatim}
import sys

fd = sys.stdout.fileno()
print(f"stdout fileno = {fd}")
name, score = "Kramer", 42
sys.stdout.write(f"{name:10} | score = {score:04d}\n")
sys.stdout.flush()
\end{verbatim}
