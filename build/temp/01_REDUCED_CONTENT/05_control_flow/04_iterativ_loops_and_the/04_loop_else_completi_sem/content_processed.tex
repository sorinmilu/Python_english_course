\subsection{Loop-\texttt{else} Completion Semantics}

Python attaches an optional \texttt{else} block to \texttt{for} and \texttt{while} loops. The keyword is misleading: loop-\texttt{else} is not conditional failure handling. It is a \emph{fall-through target} wired into the loop's control-flow graph, reachable only when the loop exits without executing \texttt{break}.

\subsubsection{The Loop Else Semantic Paradox: Executing Blocks Beyond Iteration Boundaries}

At bytecode level, a \texttt{for} loop compiles to a \texttt{GET\_ITER}/\texttt{FOR\_ITER} cycle. \texttt{FOR\_ITER} jumps to the loop-\texttt{else} entry when the iterator raises \texttt{StopIteration}---natural exhaustion. A \texttt{break} inside the body emits an unconditional jump that \emph{bypasses} that fall-through edge entirely, landing after the whole loop structure (including the \texttt{else} block).

\begin{verbatim}
for item in items:
    if found(item):
        break          # unconditional jump -> after loop+else
else:
    handle_not_found() # reached only via FOR_ITER exhaustion path
\end{verbatim}

The graph shape:

\begin{verbatim}
FOR_ITER --StopIteration--> else_block --> merge_point
    |
    v (value available)
 loop_body --break--> merge_point   (skips else_block)
    |
    JUMP_BACKWARD to FOR_ITER
\end{verbatim}

The same fall-through rule applies to \texttt{while}: the \texttt{else} runs when the condition test fails at the loop head (normal exit), not when the condition was false before the loop ever ran. \texttt{continue} skips to the next iteration without triggering the \texttt{else}; only \texttt{break} and exceptional unwinding suppress it.

Search-without-flag idioms map directly onto this edge: the loop body uses \texttt{break} on success; the \texttt{else} block is the ``no \texttt{break} occurred'' completion route---not an error handler, but the structural path taken when the back-edge terminates without an explicit exit jump.

If an unhandled exception propagates out of the loop body, the loop does not complete normally and the \texttt{else} block is skipped---the exceptional edge takes precedence over the exhaustion fall-through, just as \texttt{break} does.

\begin{quote}
Read loop-\texttt{else} as ``merge label after normal iterator exhaustion,'' not as ``the opposite of \texttt{if}-\texttt{else}.''
\end{quote}
