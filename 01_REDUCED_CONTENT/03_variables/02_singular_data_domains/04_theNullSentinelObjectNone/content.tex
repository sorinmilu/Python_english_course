\subsection{The Null-Sentinel Object (\texttt{None})}

Python uses \texttt{None} to represent absence, missing result, or ``no useful value here.'' It is not zero, an empty string, an empty list, or \texttt{False}. Its type is \texttt{NoneType}; it is falsy but not equal to \texttt{False}.

\subsubsection{\texttt{None} as a Singleton Object, Not a Null Pointer}

In C, a null pointer indicates no valid target. Python's \texttt{None} is a real heap object with type, identity, and reference count. There is one \texttt{None} singleton per process; \texttt{a is None} and \texttt{b is None} imply identical addresses.

This differs from an unbound name. \texttt{value = None} means the name exists and refers to the \texttt{None} object. Reading an undefined name raises \texttt{NameError}. \texttt{None} is not ``no variable''; it is an object signaling no useful value.

\subsubsection{Absence, Default Return Values, and Missing-Value Signaling}

Functions without an explicit \texttt{return} statement return \texttt{None} automatically. \texttt{None} commonly marks optional or missing data:

\begin{verbatim}
middle_name = None    # absence of value
middle_name = ""      # empty string: value exists, length zero
\end{verbatim}

Both are falsy in boolean context, but they answer different questions. \texttt{None} means no value was supplied; \texttt{""} means a string was supplied with no characters.

Testing for absence requires identity, not equality alone:

\begin{verbatim}
if value is None:       # correct: tests singleton identity
if value is not None:   # correct: present (may still be falsy)
\end{verbatim}

Using \texttt{if value:} conflates absence with other falsy values such as \texttt{0}, which may be legitimate data.

\subsubsection{Identity Testing with \texttt{is None} and \texttt{is not None}}

Because \texttt{None} is a singleton, \texttt{is None} asks the precise question: does this name refer to the one \texttt{None} object? The operator \texttt{==} asks value equality, which custom classes may override; \texttt{is} compares pointer identity directly.

The practical summary:

\begin{quote}
\texttt{None} is Python's singleton sentinel for absence or no useful result. It is not a null pointer and not interchangeable with \texttt{False}, zero, or empty containers. Test it with \texttt{is None} and \texttt{is not None}.
\end{quote}
